# Load Multi Image 节点说明

节点名称：`Load Multi Image（多图合并）`
节点分类：`WZF_laowangtools`

主要功能：
- 提供图像列表输入插槽 `imglist`，用于输入图像批次。
- 提供 20 个可选的图像输入插槽（`image_0` … `image_19`），这些插槽均为 optional，不连接也不会报错。
- 支持 `imgurl` 文本输入（每行一个图片 URL 或本地路径），也可以把文本节点直接连接到该输入。
- **输入顺序**：依次处理 `imglist` → `image_0`…`image_19` → `imgurl` 文本加载的图像。
- 输出：
  1. `图像列表`：包含所有有效图像的列表（便于批量导出）。
  2. `图像_0` … `图像_19`：对应 20 个独立输出插槽，只输出图像列表中的前20个图像，若没有图像则输出 `None`。
  3. `输入端图像总数量`（字符串）：等于 imglist图像数量 + 插槽内有效图像数量 + 文本 URL 成功加载的图像数量。
  4. `输出端图像总数量`（字符串）：实际输出的有效图像数（以图像列表数量为准）。

使用说明：
1. 如果你有本地或网络图片希望作为单独图像输出，可以把它们分别连接到 `image_0` … `image_19` 插槽（不需要全部连接）。
2. 如果你有多个图片链接（文本形式），可以把每个链接一行放在 `imgurl` 文本节点中并连接到该节点，节点会尝试下载并解析每个链接（下载使用重试机制以提高成功率）。
3. 节点会合并插槽中的图像与 `imgurl` 文本中加载到的图像，形成 `图像列表` 和逐一对应的 20 个图像输出（不足位会以 `None` 填充）。
4. 如果某个 URL 无法下载或解析，会被跳过，不会导致整个节点失败。
5. 下载健壮性说明：
   - 本节点采用了先进的下载策略：使用 requests.Session + Retry 重试机制、HEAD 预检（若支持）、流式分块读取和多种 User-Agent/Referer headers 的尝试以提高在 OSS/CDN 上的命中率与容错性。
   - **智能异常分类**：区分代理错误、SSL证书错误、普通网络异常等不同类型，提供针对性的处理策略。
   - **快速失败机制**：对于代理配置问题等不可重试的错误，立即放弃避免浪费时间。
   - **分层超时策略**：HEAD检查(5-10s)、GET下载(10-25s)、总超时保护(40s)，适应不同网络环境。
   - **详细调试信息**：控制台输出完整的下载过程，便于排查网络问题。
   - 对于需要签名或受限的 OSS 资源（私有 bucket），请传入预签名 URL 或确保对象可公开访问。
   - 如果你遇到个别链接无法下载，可先将这些链接在浏览器或 curl 中测试 HEAD/GET，确认服务器返回的状态与 content-length，再反馈给我以便进一步诊断。

6. 调试信息说明：
   - 节点运行时会在控制台输出详细的下载调试信息，包括：[DEBUG] Starting _fetch_url_content_with_retries、[DEBUG] HEAD check、[DEBUG] GET request 等。
   - 加载报告输出会显示每个URL的处理状态：OK（成功）、FAILED（失败原因）。
   - 常见错误类型：
     - `ProxyError`：代理配置问题，会立即放弃重试
     - `SSLError`：SSL证书问题，会尝试降级处理
     - `ConnectionError/Timeout`：网络连接问题，会正常重试
   - 如果遇到大量失败，建议检查网络环境和代理设置。

注意事项：
- 节点预置了 20 个插槽以保证兼容性与可视化的一致性；如果你不想在画面上看到太多插槽，请将该节点放在合适的位置或使用项目组织布局。
- 因为 ComfyUI 的节点元信息在某些版本中对动态变更支持有限，本节点选择了“固定 20 插槽”的实现方式以保证稳定性与兼容性。

示例：
- 把一个 `多行文本` 节点内容填入若干图片链接（每行一个），连接到本节点的 `imgurl`，然后运行图即可在输出插槽看到下载后的图片。
